# Architecture

| Boundary                                       | Responsibility and rule                                                                                                                                                                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/domain/model.ts`                          | Canonical schemas for goals, separate support areas, work references, onboarding drafts, accepted answer snapshots and commitment revisions. No React or I/O.                                                                         |
| `src/domain/migration.ts`                      | Reads old documents without losing IDs or records. Legacy support-priority goals remain goals because their original meaning is ambiguous. Promotes genuinely signed old drafts into commitment history.                              |
| `src/domain/onboarding.ts`                     | Draft creation, answer-to-context conversion, proposal mapping, validation and atomic acceptance. Raw narrative stays independent of edited goals. Re-acceptance is idempotent by proposal revision; first-action IDs remain stable.  |
| `src/domain/coach.ts`                          | Provider-independent validated context, questions, plan and commitment formats. Exactly one core outcome; ongoing areas are a separate collection.                                                                                    |
| `src/domain/planning.ts`                       | Conflict checks, date-aware goal coverage, timestamp-derived countdown math and rule-based scheduling. Area work keeps its own reference and does not count against goal targets.                                                     |
| `src/application/ports.ts`                     | Persistence contract. The application receives an implementation at composition time.                                                                                                                                                 |
| `src/application/coach-port.ts`                | `PlanningCoach` contract for questions, proposal and commitment. Provider details and secrets are outside application policy.                                                                                                         |
| `src/application/plan-season.ts`               | Calls the selected coach and validates each response before returning a new proposal. Does not accept or mutate the workspace.                                                                                                        |
| `src/application/store.ts`                     | Commands validate and persist before publishing. Supports area CRUD, focus, resuming/cancelling setup, atomic acceptance and re-signing. Failed writes preserve the previous snapshot.                                                |
| `src/infrastructure/guided-coach.ts`           | Explicit local topic heuristics and a basic editable outline. No network or claim of language-model reasoning.                                                                                                                        |
| `src/infrastructure/connected-coach.ts`        | Same-origin API adapter, timeout, abort forwarding and readable invalid-response errors. No browser credentials or direct provider requests.                                                                                          |
| `server/coach-handler.ts`                      | Optional OpenAI-compatible provider adapter, server-only environment config, loopback-origin checks, bounded requests/responses, timeout and structured validation.                                                                   |
| `server/main.ts`, `server/static-handler.ts`   | Local production HTTP server and static app hosting. Rejects traversal, hidden files and outside symlinks. Importing the factory does not start a server.                                                                             |
| `src/bootstrap.ts`                             | Wires browser persistence, cross-tab events and coach adapters. React connects through `src/ui/useWorkspace.ts`.                                                                                                                      |
| `src/ui/pages/Onboarding.tsx`                  | Owns interaction and pending-request lifecycle. Back/cancel aborts requests; request tokens reject late responses. Saves exact question index and answers.                                                                            |
| `src/ui/onboarding`                            | Separate presentation components for dates, narrative, conversation, plan review and commitment, with scoped styling. Review edits a draft, not live workspace records.                                                               |
| `src/ui/pages/Season.tsx`                      | Accepted goals and areas, current signed commitment, previous revisions and original planning notes.                                                                                                                                  |
| `src/infrastructure/storage.ts`, `calendar.ts` | Migration-aware browser repository, bounded JSON parsing, downloads and RFC 5545 snapshot export. Corrupt saved bytes remain recoverable.                                                                                             |
| `extension`                                    | Independent MV3 navigation blocker with validated fixed planner origins, ephemeral rules and an expiring heartbeat lease.                                                                                                             |
| Acceptance and history                         | A successful save adds linked goals, tasks, optional block, separate support areas, an accepted input snapshot and a signed revision together. Existing work is retained. Replanning task IDs upsert instead of duplicating.          |
| Time and concurrency                           | Civil local dates for planning, epoch timestamps for focus. Timer derives from timestamps rather than interval counts. Browser profiles do not sync, concurrent edits use last-write-wins, and clock changes may affect elapsed time. |
| Deployment                                     | Static guided app or local single-user Node server. Remote multi-user deployment requires authentication, authorization, quotas and an explicit data policy before exposing coaching.                                                 |
