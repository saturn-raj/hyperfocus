# First-run season setup

| Decision        | Implementation                                                                                                                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Problem         | The initial release opened a populated calendar and omitted the product’s guided first-run experience.                                                                                                                                             |
| Research        | Publicly served Superfocus onboarding assets identify introductions, season length, a brain dump, follow-up questions, a reviewed goal plan and a signed commitment. Authenticated execution and generated answers are unverified.                 |
| Flow            | Welcome → season dates/name → brain dump → reason, outcome and first action per goal → capacity → review with optional first block → commitment and signature → season overview.                                                                   |
| Alternatives    | A short product tour would explain controls without creating a plan. A remote conversational coach would require a provider and credentials. This implementation walks through meaningful decisions and produces a usable personal season locally. |
| Honest behavior | Explicit user-written lines become goals. Prompts, priority checks and capacity validation are deterministic. No fake generation delays or remote-coach claims.                                                                                    |
| Persistence     | Application commands save partial drafts immediately. New browsers start empty; examples require an explicit choice. Old backups default to incomplete setup and keep all existing records.                                                        |
| Completion      | Validate every required stage and construct linked goals, milestones, actions and optional block in a single save. Reject conflicts without partial writes. Keep the signature and commitment visible in the season.                               |
| Architecture    | Domain functions own rules; application commands own persistence; separate UI step components render fields; the page controller owns navigation.                                                                                                  |
| Verification    | Domain tests cover parsing, priorities, capacity, completion, conflict handling and legacy reads. Desktop/mobile workflows cover resumability, complete setup and preservation of existing work.                                                   |
