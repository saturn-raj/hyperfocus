# REA-guided rebuild

| Decision           | Result and reason                                                                                                                                                                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Evidence first     | Install the requested REA skill and compatible CLI globally. Inspect selected shipped browser artifacts, preserve Evidence IDs/hashes, and keep static facts distinct from runtime and server unknowns.                                             |
| Product correction | Replace fixed per-goal forms with a free-form narrative, relevant questions one at a time, an editable reviewed plan, and a signed commitment.                                                                                                      |
| Support areas      | Give ongoing areas their own entities and work references. Keep outcome priorities core/secondary. Preserve ambiguous legacy supporting goals rather than guessing their original meaning.                                                          |
| Provider boundary  | Application owns a PlanningCoach port; local and connected implementations are adapters. Connected credentials live on an optional local server. Default guided mode requires neither a server provider nor an API key.                             |
| Choice and privacy | Clearly identify both modes. Only connected mode sends context to a configured provider after the user continues. Save original narrative and answers independently of generated/edited entities.                                                   |
| Acceptance         | Commit the reviewed proposal atomically and idempotently. Stable first-action identities prevent duplicates when revisiting setup. Preserve existing work and earlier signed revisions.                                                             |
| Returning user     | Starting a new draft does not remove the accepted season or promise. Cancel returns to that season. Re-signing adds a revision.                                                                                                                     |
| Architecture       | Preserve domain/application/infrastructure/UI boundaries, add a dedicated proposal service and provider schemas, and isolate onboarding styles and steps.                                                                                           |
| Validation         | Domain/application/migration/server tests, desktop/mobile guided and fixture-provider workflows, real local production smoke test, visual checks and targeted accessibility audit. Live provider and original authenticated flow remain unverified. |
