# Coaching configuration

| Topic             | Behavior / action                                                                                                                                                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default           | Private guided mode. Topic-based follow-ups with selectable answers, custom input and an editable local outline; no provider calls or API key. It does not reproduce Superfocus’s private model or prompt.                                      |
| Connected mode    | An optional OpenAI-compatible chat-completions provider generates questions, outcome goals, support areas and an unsigned commitment draft. The user reviews and signs.                                                                         |
| Configure         | Copy `.env.example` to `.env`. Set `COACH_BASE_URL` to a base ending in `/v1` where appropriate, and `COACH_MODEL` to an available model. Set `COACH_API_KEY` for remote HTTPS providers. Restart dev/production after changes.                 |
| Local Ollama      | Use `COACH_BASE_URL=http://127.0.0.1:11434/v1` and an already-installed model in `COACH_MODEL`. Loopback HTTP may omit the API key. Ollama and models are not installed by this project.                                                        |
| Secret boundary   | `.env` is ignored by Git. Credentials are read only by Vite’s server middleware or the production Node process. Never use a `VITE_` prefix for a credential.                                                                                    |
| Dev               | `npm run dev` loads the unprefixed `COACH_` settings from `.env` on the server.                                                                                                                                                                 |
| Production        | `npm run build`, stop dev, then `npm start`. Node loads `.env` and serves the app/API on `127.0.0.1:5180`.                                                                                                                                      |
| Status            | `GET /api/coach/status` reports configured state and provider hostname only. It validates configuration, not provider availability, credentials or model existence.                                                                             |
| Requests          | `POST /api/coach` with `action` questions, plan or commitment plus a validated context. Successful envelopes are `{questions}`, `{plan}` or `{commitment}`.                                                                                     |
| Sent data         | Narrative, name, season length and non-skipped answers; the reviewed plan is included for commitment drafting. Choosing connected mode and continuing triggers sending this data to the configured provider. Provider retention policies apply. |
| Validation        | Response schemas separate core/secondary outcomes from maintenance areas. Invalid provider output, rate limiting, credential rejection and timeouts surface errors; saved answers remain available for retry.                                   |
| Bounds            | 64 KB request, 256 KB provider response, 30-second provider deadline. The browser adds a 35-second request deadline. Back and Cancel abort browser requests; the server deadline bounds upstream work.                                          |
| Local access      | API host must be loopback. Browser origins must match the local host and port; cross-site requests are rejected. The server is not a public authenticated API.                                                                                  |
| Static deployment | Serves guided mode. Without the optional API, connected mode stays unavailable. No credential is embedded in the static build.                                                                                                                  |
| Verification      | Fake-provider tests cover envelopes, malformed output, status/origin/body bounds, credentials and timeout handling. Browser tests exercise connected flow using fixtures. A live model was not called during implementation.                    |
